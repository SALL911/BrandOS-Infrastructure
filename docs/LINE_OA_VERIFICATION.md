# LINE 官方帳號 — 認證帳號（灰盾）申請
## 全國區塊鏈會計聯合會 ｜ v1.0 ｜ 2026-08-30

---

## 〇、先講清楚：哪一步不能自動化

**LINE 官方帳號的「認證帳號」申請沒有公開 API。**

申請只能由帳號管理者在 LINE Official Account Manager 後台人工提交，
並上傳法人登記文件供 LINE 台灣團隊人工審核。沒有任何程式化提交的途徑，
也不存在能代為送件的第三方 API。任何宣稱能「自動申請」的工具都不可信。

**所以本文件把工作切成三段**：

| 階段 | 可否自動化 | 本 repo 提供什麼 |
|------|-----------|-----------------|
| 1. 送件前置 | ❌ 人工 | 文件清單 + 逐欄預填內容（§二、§三）|
| 2. LINE 人工審核 | ❌ 等待 | 時程與退件原因對照表（§四）|
| 3. 通過後的串接 | ✅ 可自動化 | Messaging API → Make → HubSpot（§五）+ 22 縣市來源追蹤（§六）|

---

## 一、三種帳號的差別（先確認要申請哪一種）

| 類型 | 盾牌 | 誰能申請 | 關鍵差異 |
|------|------|---------|---------|
| 一般帳號 | 灰色（無盾）| 任何人 | 註冊即得 |
| **認證帳號** | **灰盾** | **法人／團體／商家** | **可被 LINE 站內搜尋、可買 LINE 廣告、可用付款功能** |
| 企業帳號 | 綠盾 | LINE 主動邀請 | 不能主動申請 |

聯合會要的是**認證帳號（灰盾）**。綠盾不接受申請，不用花時間。

> **公信力價值**：灰盾讓聯合會的帳號在 LINE 站內可被搜尋到。
> 對「22 縣市 × 政府／媒體／宗教組織」的對口而言，這是可信度的最低門檻——
> 沒有盾牌的帳號，對方單位的承辦人不會加。

## 二、送件前置（沒有這些就別送，退件率極高）

### 2.1 法人文件（聯合會端）

- [ ] **人民團體立案證書**（內政部核發）影本
- [ ] **法人登記證書**（若已完成法人登記）
- [ ] **統一編號**（稅籍登記或法人登記之統一編號）
- [ ] **最近一次理事會改選核備函**（主管機關核備）
- [ ] **理事長身分證明**

### 2.2 理事會決議（§三 的授權來源）

LINE 官方帳號屬於**法人資產**，不是個人帳號。送件前理事會必須決議：

1. **同意以聯合會名義開設 LINE 官方帳號**
2. **指定帳號管理者**（姓名 + 職稱 + 是否具對外代表權）
3. **通過個資蒐集告知條款**
   （特定目的：產業研究與活動通知；蒐集項目：姓名、單位、職稱、公務聯絡方式）

> 詳見 `docs/NGO_ENTITY_STRUCTURE.md` §2.1。
> **這三項未決議前不要送件**——LINE 審核會要求證明送件人有權代表法人。

### 2.3 個資法紅線（寫進帳號設定，不是事後補）

- LINE OA 的加好友歡迎訊息**必須**包含個資蒐集告知連結
- 標籤功能**絕對不可**用來標記個人宗教信仰（個資法第 6 條特種個資）
- 宮廟／教會以**組織**身份進 HubSpot，LINE 端只記錄「來源縣市 + 場合」

## 三、申請表逐欄預填內容

在 LINE Official Account Manager → 設定 → 帳號設定 → 申請認證帳號。
以下為建議填寫內容，送件前請理事長確認：

| 欄位 | 填寫內容 |
|------|---------|
| 帳號名稱 | 全國區塊鏈會計聯合會 |
| 帳號類型 | 團體／組織（非商家）|
| 產業類別 | 團體組織 → 公協會 |
| 公司／團體名稱 | 全國區塊鏈會計聯合會（須與立案證書完全一致）|
| 統一編號 | （填入法人統編）|
| 登記地址 | （須與立案證書完全一致）|
| 代表人 | （理事長姓名，須與核備函一致）|
| 聯絡人 | （理事會決議指定的帳號管理者）|
| 聯絡電話 | （聯合會市話優先，手機次之）|
| 官方網站 | （聯合會官網；若無，用 symcio.tw 的聯合會專頁）|
| 帳號用途說明 | 發布區塊鏈會計標準、認證與培訓資訊，並與 22 縣市政府、產業公會、學研及社群單位進行公務聯繫。 |

**填寫鐵則**：名稱、地址、代表人**三者必須與立案證書逐字相同**。
差一個字（例如「臺」寫成「台」）就會退件。

## 四、審核時程與退件原因

| 項目 | 實際狀況 |
|------|---------|
| 審核天數 | 約 5–10 個工作天（旺季更久）|
| 退件後 | 可補件重送，但會重新計算天數 |

**常見退件原因（依發生頻率）**：

1. 團體名稱與立案證書不一致（含全形／半形、臺／台）
2. 登記地址與證書不符
3. 代表人姓名與最新核備函不符（改選後未更新最常見）
4. 官方網站無法連線，或網站上找不到該團體名稱
5. 帳號用途說明過於商業化（NGO 帳號寫成賣服務會被質疑）

> 第 5 點特別注意：聯合會的用途說明**不要出現任何商業服務字眼**。
> 商業收入走 Symcio，這條在 `docs/NGO_ENTITY_STRUCTURE.md` §2.2 已定。

## 五、通過後的自動化接點（這段可以程式化）

灰盾核准後，才有以下可自動化的部分：

### 5.1 取得 Messaging API 憑證

LINE Official Account Manager → 設定 → Messaging API → 啟用
→ 取得 `LINE_CHANNEL_ID` / `LINE_CHANNEL_SECRET` / `LINE_CHANNEL_ACCESS_TOKEN`

**憑證一律進 GitHub Secrets，不落地到 repo**（CLAUDE.md §9.2）。

### 5.2 加好友 → HubSpot 自動建檔

```
LINE follow webhook
  → Make.com scenario（免費版 1,000 ops/月）
    → HubSpot: create/update contact
       brandos_source_node   = line_oa
       brandos_county_city   = （由 §六 的來源參數帶入）
       brandos_consent_basis = line_oa_notice
       brandos_relationship_stage = contacted
```

**Make 免費版額度試算**：19 家代理商 + 22 縣市節點，
即使每月新增 300 位聯絡人、每位觸發 2 次操作，也只用掉 600 ops，額度充裕。

### 5.3 訊息額度的正確用法

輕用量方案每月 200 則免費訊息。**不要拿來群發**：

| 用途 | 算不算訊息額度 |
|------|--------------|
| 一對一回覆 | ✅ 算（額度留給這個）|
| 圖文選單（Rich Menu）| ❌ 不算 |
| 自動回應訊息 | ❌ 不算 |
| 標籤分眾 | ❌ 不算 |

所以：**大量觸達靠圖文選單 + 自動回應 + 標籤分眾，200 則全部留給真人一對一。**

## 六、22 縣市來源追蹤（不開 22 個帳號）

**只開一個 LINE OA。** 22 縣市不是 22 個帳號，是 22 組標籤。

### 6.1 轉址頁做法

在 symcio.tw 建立轉址端點，掃碼者先經過它再進 LINE OA：

```
https://symcio.tw/j/{county}-{occasion}
  → 記錄來源（POST 到 Make webhook）
  → 302 轉址至 https://line.me/R/ti/p/@{basicId}
```

每個縣市／場合印一張自己的 QR code（指向各自的 `/j/...`），
掃碼即自動帶入 `brandos_county_city` 與 `brandos_line_user_ref`。

> 這個做法不依賴 LINE 的任何付費或認證專屬功能，一般帳號時期就能先跑。
> 認證帳號核准後直接沿用，不用重印 QR code。

### 6.2 縣市代碼

代碼與 `schemas/hubspot_crm_schema.json` 的 `brandos_county_city` 列舉值完全一致
（taipei / new_taipei / taoyuan / taichung / tainan / kaohsiung / keelung /
hsinchu_city / hsinchu_county / miaoli / changhua / nantou / yunlin /
chiayi_city / chiayi_county / pingtung / yilan / hualien / taitung /
penghu / kinmen / lienchiang）。

### 6.3 先攻哪幾個縣市

不要 22 個一起做。先做**有實體節點**的：

| 優先 | 縣市 | 既有節點 |
|------|------|---------|
| P0 | 臺北市 | 18 家媒體代理商 + MAA 公會（全部在臺北）|
| P1 | 臺中市 | 霧峰（阿罩霧文化基金會）|
| P1 | 南投縣 | 既有節點 |
| P1 | 嘉義縣市 | 既有節點 |
| P2 | 其餘 18 縣市 | 等前四個做出示範案再開 |

## 七、執行順序

1. **理事會決議**（授權開帳號 + 指定管理者 + 通過個資告知條款）— §2.2
2. **備齊法人文件** — §2.1
3. **人工送件**（逐欄比對立案證書）— §三
4. 等待審核 5–10 個工作天 — §四
5. 核准後啟用 Messaging API，憑證進 GitHub Secrets — §5.1
6. 建 Make scenario：LINE follow → HubSpot — §5.2
7. 上線 `/j/{county}` 轉址頁，先做臺北市 — §六
8. 印 QR code，先給 MAA 與 18 家代理商 — `data/crm/agency_partners.csv`
